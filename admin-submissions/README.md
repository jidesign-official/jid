# 포트폴리오 게시 패키지

`https://jid.kr/admin/`에서 만든 **프로젝트 코드와 같은 이름의 ZIP**을 이 폴더에 업로드하세요. 예: `jd046.zip`.

1. 편집기에서 대표 이미지와 본문을 작성합니다. 이미지 블록은 여러 장/2·3·4열을 지원합니다. GLB는 선택 사항입니다.
2. ZIP을 다운로드합니다. 브라우저 초안은 다른 컴퓨터나 GitHub에 자동 동기화되지 않습니다.
3. GitHub에 로그인하고 이 폴더의 **Add file → Upload files**에서 ZIP을 업로드합니다. `main`에 커밋해야 현재 사이트에 배포됩니다. 브랜치/PR로 올렸다면 검토 후 main에 병합하세요.
4. 저장소 **Actions → Deploy Next.js site to Pages**에서 검증·배포 결과를 확인합니다. 업로드 커밋 성공은 배포 성공과 다릅니다.

- 파일명은 `<프로젝트코드>.zip`이어야 합니다. GitHub 웹 업로드 및 편집기 한도는 ZIP 한 개당 25MiB입니다. 큰 파일은 크기를 줄여 주세요. 유료 서비스는 자동으로 사용하지 않습니다.
- 새로 올리는 GLB는 기본 삼각형(TRIANGLES) 방식이며 키프레임 애니메이션·스켈레톤 변형·모프 타깃이 없는 정적 제품 모델만 지원합니다. GLB 하나당 메시·노드·장면의 반복 참조도 합산한 처리량을 64MiB로 제한합니다. 파일 용량과 별도의 보수적 검증 기준이며 실제 GPU 메모리 상한을 의미하지 않습니다. Strip/Fan·선·점 모델이나 한도를 넘는 모델은 제작 도구에서 기본 삼각형으로 내보내거나 단순화해 주세요. 자동 변환·데이터 제거는 하지 않습니다. 뷰어의 마우스·터치 회전과 확대는 그대로 사용할 수 있습니다. 위험한 반복 참조로 브라우저 메모리가 과도하게 사용되는 것을 막기 위한 제한이며, 기존 프로젝트의 원본 GLB와 뷰어 동작은 바꾸지 않습니다.
- GLB의 텍스처·샘플러 정의는 각각 최대 128개입니다. 공유 이미지라도 기본·대체 이미지 참조와 색공간별 업로드 가능성을 합산한 텍스처 처리량은 4천만 base-level pixel units 이하여야 합니다. 이 역시 실제 GPU 메모리 상한이 아닌 보수적 작업량 기준입니다.
- GLB의 부가정보(메타데이터) 복제 작업량도 별도로 64MiB 한도를 적용합니다. 개별 개수 제한 이내라도 전체 처리량을 넘으면 거부되며, 원본 메타데이터를 자동 삭제하거나 변환하지 않습니다.
- 바이너리 영역과 이미지 원본 복사량도 GLB당 별도로 합산해 64MiB로 제한합니다. 영역이 겹치거나 원본이 같더라도 각 선언·이미지 항목을 계산하며 자동 자르기·변환은 하지 않습니다.
- 초안 불러오기도 현재 GLB 검증을 거칩니다. 미완성 제목·본문은 계속 불러올 수 있지만 지원하지 않는 모델이 있으면 복원이 중단됩니다. 저장 기록과 원본 데이터는 자동 삭제·변환하지 않습니다.
- 기존 69개 레거시 프로젝트 코드는 보호되며 ZIP으로 덮어쓸 수 없습니다. 새 코드(예: `jd046`)를 사용하세요.
- 새 형식 프로젝트를 수정할 때는 원래 ZIP을 편집기로 불러와 수정한 뒤 같은 이름의 ZIP을 교체하세요. ZIP을 GitHub에서 삭제하면 다음 성공 빌드부터 해당 새 형식 프로젝트가 목록에서 빠집니다. Git 이력에서 이전 ZIP을 복원해 되돌릴 수 있습니다.
- 검증에 실패하면 새 배포를 중단하고 기존 정상 사이트를 유지합니다. Actions 로그의 오류를 수정한 ZIP으로 교체하거나, 잘못 올린 ZIP을 삭제한 뒤 다시 커밋하세요.
- 모든 패키지는 빌드 시에만 검증·전개합니다. 기존 이미지·GLB·엑셀과 원본 메타데이터를 재작성하지 않습니다.
- 이 저장소와 제출된 ZIP은 공개됩니다. 개인정보·비밀번호·토큰·비공개 자료를 넣지 마세요.

## 파일명과 업로드 매뉴얼

편집기의 **업로드 매뉴얼** 버튼으로 준비·파일 구분·블록 편집·게시 순서를 팝업에서 확인할 수 있습니다.

프로젝트 코드가 `jd046`일 때 ZIP 내부 파일명은 다음처럼 자동 정리됩니다.

- 대표 이미지: `assets/jd046_thumbs.webp`
- 본문 이미지: `assets/jd046_body_01.webp`, `assets/jd046_body_02.webp` …
- 3D 모델: `assets/jd046_model_01.glb`, `assets/jd046_model_02.glb` …
- 위 예시의 이미지 확장자는 업로드한 형식에 따라 `.png`, `.jpg`, `.jpeg`, `.webp`를 그대로 사용합니다. 확장자만 바꿔 이미지 형식을 변환하지 않습니다.

이미지는 미리 원하는 비율로 준비한 뒤 **대표 이미지 선택** 또는 **블록의 이미지 추가**로 역할을 지정하세요. 업로드 전 파일명은 자유롭게 지어도 됩니다. 편집기가 ZIP을 내보낼 때만 이름을 정리하며 컴퓨터의 원본 파일명이나 이미지·GLB 바이트는 변경하지 않습니다. 원래 파일명도 패키지 정보에 보관합니다.

본문 번호는 블록과 이미지의 표시 순서, 모델 번호는 모델 표시 순서를 따릅니다. 같은 이미지 에셋을 여러 곳에 재사용했다면 파일을 중복 복사하지 않고 최초 지정된 파일을 다시 참조합니다. 블록/이미지 순서를 변경한 뒤 새 ZIP을 내보내면 번호도 그 순서에 맞춰 갱신됩니다.

## 계정과 권한

편집기는 공개된 정적 도구이며 자체 로그인/비밀번호/권한 데이터베이스가 없습니다. 실제 업로드 권한은 GitHub가 검사합니다.

- **저장소 소유자**: 게시 및 Settings의 협업자 초대·권한 회수.
- **쓰기 권한 협업자**: GitHub에서 게시 커밋 가능. 콘텐츠만이 아니라 저장소 소스 전체에 쓰기 권한을 갖습니다.
- **초대받지 않은 사용자**: 편집/ZIP 생성은 가능하지만 이 저장소에 게시할 수 없습니다.

초대·삭제는 `https://github.com/jidesign-official/jid/settings/access`에서 처리합니다. GitHub 계정에 2단계 인증을 사용하는 것을 권장합니다. 인증정보를 채팅이나 편집기에 입력하지 마세요.

기술 형식과 제한은 [관리자 패키지 계약](../docs/admin-package-format.md)을 참고하세요.
