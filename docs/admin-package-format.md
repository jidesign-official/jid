# GitHub-only portfolio publishing contract (v1)

The `/admin/` UI is a PUBLIC static offline editor, not an authenticated backend. Drafts live in the browser. GitHub login, owner/collaborator invitations and write authorization happen on GitHub. Do not request/store GitHub passwords/PATs or imply that hiding the editor authenticates anyone. Repository writers have repository-wide write access, not a content-only sandbox.

## Publishing
Export `jd046.zip` and upload through `https://github.com/jidesign-official/jid/upload/main/admin-submissions`. GitHub authenticates/authorizes that push. Existing Pages workflow imports all packages, validates and generates build-only data/media BEFORE Next build, then deploys the same source commit. No automatic source commits, secrets, external backend, D1 or R2. Failed validation stops deployment; current live site remains available. Replacing the same package updates that CMS-created project; removing it removes that generated project on the next build. Existing 69 legacy projects cannot be overwritten by a package.

## ZIP
Root `project.json` is UTF-8 JSON. All other entries must be referenced files under `assets/`; no extra files, directories, nested ZIPs, encrypted entries, symlinks, absolute paths or traversal. Filename must equal `<project.id>.zip`.

```
{
  "schemaVersion": 1,
  "project": {"id":"jd046","title":"Example","category":"Product","thumbnail":"asset-1"},
  "blocks": [
    {"id":"block-1","type":"images","columns":3,"images":[{"assetId":"asset-1","alt":"Example","caption":""}]},
    {"id":"block-2","type":"heading","level":2,"text":"Design"},
    {"id":"block-3","type":"paragraph","text":"Plain text"},
    {"id":"block-4","type":"spacer","size":"medium"},
    {"id":"block-5","type":"divider"}
  ],
  "models": [],
  "assets": [{"id":"asset-1","path":"assets/asset-1.png","name":"original.png","kind":"image","sha256":"64 lowercase hex","bytes":123,"width":1024,"height":1024}]
}
```

`id` matches `^jd\d{3}(?:_[a-z]+)?$`; title nonblank/max200, category Product or UX/UI. Asset/block IDs match `^[a-zA-Z0-9_-]{1,80}$`. Image columns 1..4; each image block 1..12 images, each image has alt max300 and caption max500. Heading level2/3 with text max200; paragraph max10000, spacer small/medium/large. Plain text only: render with React escaping, never raw HTML. Thumbnail is a required image asset. Models are an ordered array of unique model asset IDs.

Limits: ZIP <=25MiB, total uncompressed <=50MiB, <=60 assets, <=100 blocks, <=4 GLBs. Images: PNG/JPEG/WebP only, signature/dimensions checked; width/height <=8192 and pixels <=40,000,000. GLB: v2, valid declared length/chunks and JSON, no external URIs, reject Draco/Meshopt/BasisU decoder requirements (existing loader has no extra decoders). All asset lengths/SHA-256 must match. Validate before publishing any generated files. Preserve original upload bytes; do not rewrite models.

Security bounds: `project.json` <=1MiB, checked from ZIP metadata before inflation and again against actual output. JSON (including GLB JSON) is scanned before object parsing: at most 64 nested containers and 200,000 lexical tokens (strings, numbers, literals and punctuation). ZIP inflation counts actual output, stops at the declared member size or aggregate 50MiB, and requires real DEFLATE EOF with no trailing compressed bytes. Manifest asset paths and ZIP member paths must be unique after ASCII case-folding: `assets/cover.png` and `assets/COVER.png` cannot coexist. IDs and all asset references are strings, never coerced numbers.

Each GLB has a conservative 64MiB decoded-geometry budget: sum every accessor's `count × components × max(componentBytes, 4)`, plus each accessor's backing bufferView length and sparse `count × (paddedElementBytes + indexBytes)`. This includes zero-filled accessors, repeated/shared views and sparse copies; valid but expensive layouts can therefore be rejected. Accessor types/components/counts, offsets, strides, component/matrix alignment and sparse source bounds are validated; sparse indices must use unsigned byte/short/int and be strictly increasing below accessor count. `EXT_mesh_gpu_instancing` is rejected when declared in `extensionsUsed`/`extensionsRequired` or present in an extension object, even without a declaration: accessor bytes do not bound its per-node instance-matrix allocation. Independently, each uploaded GLB permits at most 1,024 mesh definitions, 4,096 total primitive definitions, 4,096 node definitions, 4,096 scene definitions, graph depth 64 nodes, and aggregate expansion of 4,096 nodes and 4,096 mesh primitives. Every scene (not only the default) counts its entire node trees and every node's mesh primitives again; shared mesh/accessor definitions do not discount distinct instances. Unused node trees count once and unused mesh definitions also consume the primitive budget, so omitting scenes cannot bypass the limits; minimal metadata without scenes remains valid. Mesh accessor, node mesh/child, scene root and default-scene references must be in-range integers (not booleans); cycles, repeated children, multiple parents and duplicate or parented scene roots are rejected before loader use. These checks apply only to newly uploaded/package GLBs, not the existing raw legacy viewers. All embedded images, whether bufferView or data URI, must match their declared MIME and valid PNG/JPEG/WebP container bytes, with the same 8192-side limit; each GLB permits at most 60 images and 40,000,000 aggregate embedded texture pixels (repeated image records count again).

Independently, each GLB permits **at most 128 texture definitions and 128 sampler definitions**, including unused definitions. Both arrays must contain objects. A texture must resolve at least one valid embedded image source; every present `texture.source`, `texture.extensions.EXT_texture_webp.source` and `texture.extensions.EXT_texture_avif.source` is validated, even with a valid fallback or no extension declaration. Sources and any present sampler reference must be in-range JSON integers, never null, booleans, strings, fractional/exponent tokens or coerced values. Sampler fields may be omitted; the current loader defaults are `magFilter=9729` (LINEAR), `minFilter=9987` (LINEAR_MIPMAP_LINEAR), `wrapS=wrapT=10497` (REPEAT). Present fields must use integer enums: mag 9728/9729; min 9728/9729/9984/9985/9986/9987; wrap 33071/33648/10497. No sampler configuration in these valid enums is prohibited. All previous image-record/40MP, MIME/container, external-URI and BasisU bans remain unchanged; these source extensions do not add AVIF image-format support.

The independent **expanded-texture processing budget is <=40,000,000 base-level pixel units per GLB**: `sum(2 × image.width × image.height for EVERY present potential source slot in EVERY texture definition)`. The source slots are core `source`, WebP alternate `source`, and AVIF alternate `source`; their costs are **summed**, not selected by priority or maximum. Even aliases of the same image in multiple slots count separately. Distinct texture definitions count again regardless of identical images or samplers, and unused definitions count. Thus a 5,000×4,000 image with one texture costs exactly 40,000,000 units; one additional 1px source/definition costs 2 more units and is rejected. Numeric accounting happens during validation before loader use, without decoding texture pixels or creating loader/GPU objects. This is a conservative work metric, **not a total GPU-memory cap**: mipmaps, decoded image memory, other buffers and renderer resources are not represented as exact bytes.

Factor 2 is audited against installed **Three.js 0.186.1** and the app's uncustomized `new GLTFLoader()`: `GLTFLoader.loadTextureImage` caches by image resource and sampler; `loadImageSource`/`Texture.copy` share `Texture.source` across clones. All built-in `assignTexture` calls either retain default `NoColorSpace` (linear/data) or set `SRGBColorSpace`; UV-channel/`KHR_texture_transform` clones change only channel/UV transforms and preserve the other WebGL texture-cache parameters. `WebGLTextures.getTextureCacheKey` includes colorSpace but not channel/UV transforms, and `initTexture` caches per shared source and that key. There are therefore at most two color-space GPU-cache variants per source/sampler configuration in this current loader path. Re-audit this assumption when changing Three.js, loader plugins/handlers, texture defaults or application texture mutations; this budget is not a promise about arbitrary future/custom loaders.

## Static-product GLB policy

User-approved scope: new uploaded/package GLBs are **static TRIANGLES-only models**, without animation, skeleton/skinning or morph deformation. Both browser and importer reject unsupported data before any loader/GPU use; this is not an animation-playback toggle or an allocation estimate.

- Root `animations` and `skins` may be absent or exactly empty arrays (`[]`). Any nonempty array is rejected, including unused definitions and harmless small animations. Present `null`, objects, strings, numbers and booleans are invalid, not equivalent to absence.
- Any node `skin` property is rejected, even when no skin is declared or the value is null/invalid. Node and mesh `weights` may be absent or empty arrays only; all nonempty arrays (including zero weights) and malformed present values are rejected.
- Every primitive's attribute keys are checked: any semantic beginning with `JOINTS_` or `WEIGHTS_` is rejected even without a declared skin. This does not prohibit ordinary static attributes or custom attributes such as `_JOINTS_0`.
- Nonempty primitive `targets` (morph targets / shape deformation) remain rejected. Empty `targets: []` remains accepted; malformed present target containers are rejected.
- Primitive `mode` must be absent (glTF's default `4`) or the integer `4` (`TRIANGLES`). All other present values are rejected: points/lines (`0`–`3`), triangle strip (`5`), triangle fan (`6`), out-of-range integers, null, booleans, strings, arrays/objects and floating-point numbers. Floating/exponent tokens such as `4.0` and `4e0` are also rejected, rather than rounded/coerced to `4`. This avoids the loader's strip/fan index-conversion expansion; export ordinary triangles instead. The rule checks later primitives and unused mesh definitions as well.

Validation covers **all** mesh/primitive/node definitions, unused definitions and nondefault scenes, not only the selected scene or first primitive. Empty metadata and bounded shared static meshes remain supported. Animation rejection prevents repeated normalized animation-output channels from multiplying Float32 conversion allocations beyond the accessor budget; morph rejection prevents repeated target slots multiplying packed renderer texture allocations. All existing JSON/ZIP/image/accessor/graph limits still apply independently. Export a baked static product model with animations, skins, joint/weight attributes and deformation data removed; validators never silently strip data or rewrite original bytes.

This policy applies only to new uploads/packages. Existing legacy project assets and raw legacy viewers are not passed through it and remain unchanged.

### Independent referenced-geometry processing budget

In addition to the existing decoded-accessor budget above, each GLB has an independent **64MiB (67,108,864 work bytes) aggregate referenced-geometry processing budget**. This is a conservative work metric, **not an exact GPU-memory cap** or a guarantee of total browser/renderer memory usage. It intentionally counts repeat references even when the loader might share/cache geometry. A small compressed or JSON-only file can still exceed it.

For a fully validated accessor `a`:

```
referenceCost(a) = a.count × components(a.type) × max(componentBytes(a.componentType), 4)
primitiveCost(p) = sum(referenceCost(a) for EVERY value in p.attributes)
                 + referenceCost(p.indices) if indices is present
meshCost(m)      = sum(primitiveCost(p) for EVERY primitive in m)
```

`components` is `SCALAR:1`, `VEC2:2`, `VEC3:3`, `VEC4:4`, `MAT2:4`, `MAT3:9`, `MAT4:16`. Component byte sizes remain 1 for 5120/5121, 2 for 5122/5123, and 4 for 5125/5126, with the four-byte floor applied above. Every attribute reference counts, including custom semantics and multiple keys aliasing the same accessor; index references count separately, even when they reference the same accessor. Neither accessor IDs nor identical primitives/mesh definitions are deduplicated.

Two counters are independently bounded at `<= 67,108,864`:

1. **Definition work:** sum `meshCost` across **all mesh definitions**, including unused meshes and GLBs with no nodes/scenes/roots. Guard each addition while reading primitive attribute/index references.
2. **Expanded work:** memoize each node subtree's `(nodeCount, primitiveCount, height, work)`; its `work` is its own mesh cost plus every child subtree cost. Bound each subtree addition early. Charge each root subtree once **per scene occurrence across every scene**, not just the default scene; then charge every unused parentless node tree once and every mesh definition unused by any node once. Shared meshes/accessors are charged for every node/scene instance. Missing/empty scenes or root lists do not exempt unused trees/definitions.

Do **not** add definition work again to expanded work: these are separate bounds, not a combined allowance. For example, a 32MiB mesh referenced by two nodes uses 32MiB definition work and exactly 64MiB expanded work and is allowed. One additional `SCALAR` element/reference at the four-byte floor makes expanded work **67,108,868 bytes (4 bytes over)** and is rejected; there is no representable one-byte increment in this metric. The same exact-boundary/+4 test applies to definition work. A repeated `VEC3` accessor with count 999,999 costs 11,999,988 bytes per reference; seven instances cost 83,999,916 bytes and are rejected even though the node/primitive counters remain below 4,096.

Both validators perform only bounded numeric accounting and graph memoization for this metric: no decoded geometry arrays, loader objects or GPU work. Structural counts are independent ceilings, not acceptance guarantees: the aggregate processing budgets can reject a model below those counts. Existing 1,024-mesh / 4,096-definition/expanded-node/primitive / depth-64 limits and every prior JSON, ZIP, image, static-deformation and accessor-layout guard remain independent and unchanged. Browser errors instruct the author to simplify the model or reduce repeated mesh/scene references; rejected data is never silently stripped or rewritten.

## Independent encoded-source-copy processing policy

Each newly uploaded/package GLB independently permits **at most 64MiB (67,108,864 work bytes) of combined encoded-source-copy work**:

```
work = sum(view.byteLength for EVERY validated bufferView DEFINITION)
     + sum(encodedByteLength(image) for EVERY image RECORD)
work <= 67,108,864
```

Every bufferView definition counts, including unused definitions, overlapping views and different indices describing the same region. A sparse accessor's full index/value backing view lengths count, not just the elements it consumes. Reusing one view index for sparse indices/values does not add a new view definition; distinct view indices count separately. For a bufferView image, `encodedByteLength` is the exact resolved view length; for a data-URI image it is the length of the actual validated decoded byte array, not base64 text length or decoded pixel storage. Each image record counts again even when many records reuse the same view, URI, image bytes or sampler configuration. A view containing an image therefore contributes once as a view definition **plus once per image record**. No cache, deduplication or loader-sharing assumption discounts these sums. Other buffer bytes outside views are not added to this metric.

Both validators validate bounds/stride and charge every view during bounded preflight **before accessor/sparse processing**. They resolve and charge every image's encoded source using remaining-budget checks **before image container/CRC validation**, retaining every existing MIME, container and image-pixel guard (including importer validation of non-core image URIs). Accounting never allocates decoded geometry, invokes the model loader or uses the GPU. Exactly 67,108,864 work bytes is allowed; one additional source byte is rejected. For example, 64 overlapping unused 1MiB views over one actual 1MiB BIN consume exactly 64MiB; adding a distinct one-byte view exceeds the limit. The bounded review fixtures with 64 full 2MiB sparse views or 60 overlapping 2MiB-ancillary PNG views now fail this independent policy; 60 image records pointing to only one such PNG view also fail.

This is the user-approved conservative **copy-work metric, not an actual peak-memory cap**: it covers full bufferView slices and encoded image-source Blob copies, not a prediction of all browser/loader/GPU allocations. File/storage, decoded geometry, referenced geometry, graph counts, image pixels, expanded textures, metadata-copy, static/TRIANGLES, JSON and ZIP guards all remain independent and unchanged. Valid models below old structural counts may fail this additional budget. The 26MiB compressible BIN compatibility case remains supported; this is not a claim that the pre-existing tokenizer accepts a 26MiB JSON generator string. Original uploaded, exported and imported asset bytes are never rewritten or stripped; legacy raw models/viewers are unchanged.

## Expanded-metadata processing policy

Each uploaded GLB independently permits **at most 64MiB (67,108,864 work bytes) of conservative metadata-copy work**, checked before any loader use. This is a source-derived processing metric, **not a total memory/GPU cap** and not a prediction of actual allocations. Valid but metadata-heavy models may be rejected. The accounting is:

```
B = UTF8 bytes of compact SOURCE JSON tokens, with only string values at
    exact core asset.generator, buffers[].uri and images[].uri counted as ""
    + 32 bytes for EVERY numeric token
C = 1 + 4 × (nodeDefs + primitiveDefs + sceneDefs + expandedNodes + expandedPrimitives)
      + 9 × (materialDefs + 1) + 4 × textureDefs + imageDefs
      + 2 × materialTextureAssignments
work = B × C <= 67,108,864
```

“Compact source tokens” means concatenating the original JSON lexical tokens without whitespace outside strings; original escapes, key spellings and number spellings remain charged. The additional 32-byte allowance per numeric token conservatively covers finite IEEE-754 number serialization growth (including exponent-to-decimal spelling), without relying on Python and JavaScript reserialization being identical. Both implementations count the same source UTF-8 tokens. Only **string values**, never keys or containers, receive the three exclusions. Core image URIs have already passed the embedded-image checks; core buffer URIs have already passed the embedded-buffer checks. No other field is omitted: all names, extras, known/unknown extensions and arbitrary fields count, including nested `extras.uri`, nested `asset.generator`, non-string generator values and literal lookalike keys such as `"images[].uri"` or `"asset.generator"`. Exclusions affect accounting only: neither parsed input nor original upload/ZIP bytes are stripped, rewritten or mutated. They do not waive lexical-parser or resource-validation failures; in particular a literal 26MiB generator string currently hits the pre-existing JavaScript token-regex stack limit even though its generator payload is excluded from this metric (the existing 26MiB compressible BIN regression remains supported).

`nodeDefs`, `primitiveDefs`, `sceneDefs`, `expandedNodes` and `expandedPrimitives` come directly from the already-validated, memoized graph counters described above. Every scene, unused parentless tree and unused mesh definition remains charged, not only the default scene or unique nodes. `materialDefs` counts **all** material definitions, including unused ones; a present `materials` must be an array of records. Texture/image definition counts include unused definitions. `materialTextureAssignments` scans **every object/array beneath every material**, including extras and unknown extensions, counting every key ending exactly in `Texture`, regardless of its value, index, actual reachability or extension declaration, without deduplication. Each such key counts once, except `metallicRoughnessTexture` counts **twice** because the loader assigns it to both metalness and roughness maps. Each opportunity is then charged for both possible texCoord and `KHR_texture_transform` clones. Comparison uses remaining budget and integer division **before multiplication**; validators never enumerate clone objects or allocate decoded arrays.

The constants are audited against installed **Three.js 0.186.1**, the app's uncustomized `new GLTFLoader()` and the existing static/TRIANGLES-only policy. `assignExtrasToUserData` retains source extras and `addUnknownExtensionsToUserData` retains unknown extension payloads on result, scene, node, mesh/primitive and material objects; node names also enter `userData.name`. `Object3D.copy`, `Material.copy` and `Texture.copy` perform `JSON.parse(JSON.stringify(source.userData))`, so these retained seeds must be charged even when geometry/images are shared. `loadMesh` can replicate mesh extras per primitive and add a mesh group; `_getNodeRef` clones shared mesh/camera/light attachments, and `loadScene` invokes `SkeletonUtils.clone` on reused root subtrees across all scenes. Four times definition/expanded node and primitive counts conservatively covers the input-bearing node wrapper, mesh group/primitive, camera, light and directional/spot target paths (target/shadow helper objects carry only fixed/default metadata). TRIANGLES excludes line/point material conversions; the three `assignFinalMaterial` boolean flags yield at most eight combinations, conservatively reserved in addition to the base material, plus the implicit default. Mesh/Object3D copies share materials and geometries rather than recursively cloning them. `loadImageSource` retains image extras and clones cached source textures; four per texture plus each image covers base/source-cache paths even with all core/WebP/AVIF source candidates. `assignTexture` can clone once for texCoord and `GLTFTextureTransformExtension.extendTexture` once more for UV transform; the recursive assignment scan includes all built-in textureInfo call sites and unknown lookalikes. Image source/cache and assignment clones share pixel sources but deep-copy metadata, so the independent texture-pixel budget cannot substitute for this check. Core data URIs are used as resource/cache inputs and never copied into `userData` or texture names (image names use URI only for non-data images, already forbidden); `result.asset = json.asset` retains generator once without cloning it into `userData`. Re-audit when Three.js, loader plugins/handlers, material modes or application cloning/mutation changes. All prior lexical, ZIP, static-deformation, accessor, graph, referenced-geometry and texture guards remain independent and unchanged.

### Existing tokenizer compatibility limit

Browser validation remains fail-closed for exceptionally long individual JSON strings: the existing JavaScript tokenizer can reject them before metadata accounting, even when file-byte limits would otherwise permit the GLB. This is a pre-existing compatibility limit, not permission to skip binary validation. Large BIN chunks and compressible ZIP size boundaries remain separately tested. The generator exclusion is verified using a parser-supported string and enough repeated nodes that the same string at a retained metadata path would exceed the aggregate work budget.

## Editor export filenames

The editor validates the source manifest first, then clones it and rewrites only `assets.path`: `<id>_thumbs.ext`, `<id>_body_01.ext` / `_02.ext` in first-use body display order, and `<id>_model_01.glb` / `_02.glb` in model order. Preserve extension/format, original `name`, stable asset IDs, references, SHA-256 and all bytes. Shared cover/body references reuse the cover path; repeated body references reuse their first path without duplicate binary files. Names are an editor-export usability convention, not the authorization or role boundary: explicit thumbnail/block/model references remain authoritative and safe older input paths remain importable. Upload inputs and the accessible **업로드 매뉴얼** dialog explain the convention and native GitHub publication steps. User originals and the69 legacy project assets are never renamed.

## Generated build format
Importer `scripts/import-admin-submissions.py --root <checkout>` reads `admin-submissions/*.zip`, protects `public/images/portfolio/portfolio_data.json` and legacy originals, and atomically writes `.generated/admin-projects.json`:

```
{"schemaVersion":1,"projects":[{"id":"jd046","folder":"jd046","title":"Example","category":"Product","image":"/_admin_media/jd046/<packageHash16>/asset-1.png","blocks":[],"models":[],"packageSha256":"..."}]}
```

Resolved image blocks use `images:[{src,width,height,alt,caption}]`; other block shapes retain their fields. Models are resolved root-relative GLB URLs. Files are extracted only beneath generated `public/_admin_media/<id>/<packageHash16>/`. `.generated/` and `public/_admin_media/` are ignored build outputs. Importer must be idempotent and reject collisions/symlinks; clean only its own marked generated subtree. Empty packages yield an empty registry. The static exported site must remain below GitHub Pages' published size limit.

## Public renderer integration
Shared types live in `src/lib/admin/types.ts`. Server-only `src/lib/adminProjects.ts` reads generated registry, returns empty when absent, rejects corrupt registry. `getAdminProjects()` / `getAdminProject(id)` expose entries. `getPortfolioCatalog()` in `src/lib/portfolioCatalog.ts` returns legacy metadata plus new CMS metadata only (no editor binaries). Home/list/detail pages consume this catalog; current featured four/order stay unchanged. Model resolver uses generated model URLs for a CMS entry, otherwise the unchanged legacy allowlist. Detail routes use the same thumbnail/square1024px template, `PortfolioBody` for CMS blocks, existing gallery/sequence fallback for legacy69, and the existing model viewer only for nonempty models. Existing CTA/navigation remain.

`/admin/` receives server catalog metadata as prop `projects`. Editor ZIP import/export round-trips this format, keeps offline IndexedDB drafts including Blob bytes, reports quota/upload/parse errors and releases preview object URLs. Preview uses `PortfolioBody` with blob image URLs and existing `Model3DViewer` with blob GLB URLs. Draft restoration applies the current binary GLB validator to every model asset (including unreferenced assets) before returning previewable state; it does not impose publication-only title/body requirements. Legacy Blob and ArrayBuffer/MIME storage formats remain readable. A rejected model produces a recoverable error and leaves the saved record unchanged; no unsupported binary is silently converted or removed. Invalid or pending assets block export. Multiple images per block, mobile stacking, captions/alt text and keyboard move controls are required. Existing published legacy items are read-only in this first version; CMS items can be updated by importing and replacing their original ZIP.
